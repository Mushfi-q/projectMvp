## 📖 Deletion Guide (Foreign Key Dependency Order):

Because the database enforces foreign key constraints, records cannot be deleted if other records still reference them. If you attempt to do so, the Admin Panel will show: **"Cannot delete ... because other records still reference it. Delete the dependent records first."**

### Dependency Chain (delete bottom-up):
```
Department
  └── Batch
        └── Semester
              └── Subject Offering ← (also depends on Subject & Faculty)
                    └── Enrollment
  └── Subject
  └── Faculty
        └── Subject Offering

Student
  └── Enrollment
```

### Safe Deletion Order:
To fully remove a Department and everything under it, delete in this order:

| Step | Delete                  | Why                                                        |
|------|-------------------------|------------------------------------------------------------|
| 1    | **Enrollments**         | They reference Subject Offerings and Students              |
| 2    | **Subject Offerings**   | They reference Subjects, Semesters, and Faculty            |
| 3    | **Students**            | They reference Batches and Semesters                       |
| 4    | **Semesters**           | They reference Batches                                     |
| 5    | **Subjects**            | They reference Departments                                 |
| 6    | **Faculty**             | They reference Departments                                 |
| 7    | **Batches**             | They reference Departments                                 |
| 8    | **Departments**         | Now safe — no children left                                |

### Quick Examples:
- **Want to delete a Department?** → First delete all its Batches, Subjects, and Faculty. But before deleting Batches, delete their Semesters. Before deleting Semesters, delete their Subject Offerings. And so on.
- **Want to delete a single Student?** → First delete their Enrollments (if any), then delete the Student.
- **Want to delete a Subject?** → First delete all Subject Offerings that use it, then delete the Subject.
- **Want to delete a Faculty member?** → First delete all Subject Offerings assigned to them, then delete the Faculty profile.

**Bug Fix — Subject Mappings Deletion Failure:**
- **Root cause:** The "Delete" button failed silently. Three issues discovered:
  1. Backend (`admin.py`): The `_count_dependents` endpoint strictly checked `if entity == "subject_offering"`, failing to process the hyphenated `"subject-offering"` string sent from the frontend.
  2. Frontend (`admin.js`): Tried to access `Object.keys()` on a failed response data payload and didn't catch undefined data if the server returned a 500 error, leaving the `window.confirm` box broken.
  3. Backend (`admin.py`): The `DELETE /admin/subject-offering/{id}` endpoint relied on `_cascade_delete_subject_offerings()` but lacked a final `db.commit()`, causing the database to silently roll back the transaction while returning a successful HTTP response.
- **Fix:** 
  - Updated `admin.py` to accept both `"subject-offering"` and `"subject_offering"`.
  - Updated `admin.js` to properly catch and log dependency check failures without crashing the `window.confirm` UI flow.
  - Added `db.commit()` to the `delete_subject_offering` endpoint to ensure the SQL deletion queries are persisted.
